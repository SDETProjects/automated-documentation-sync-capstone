# CLAUDE.md

Guidance for working with the Automated Documentation Sync capstone project.

## The 8-Step Agentic SDLC Pipeline

This repository implements an **agentic SDLC** — a deterministic pipeline driven by GitHub Copilot Chat, with CLI tools for verification and code generation.

### Two operating modes

| Mode | Steps 1-4 | Steps 5-8 | Demo entry point |
|---|---|---|---|
| **Copilot Chat (Pipeline A)** | Manual, Copilot-authored, using `.github/prompts/step-N-*` | Manual, Copilot-authored | `/run-pipeline JIRA-ID` |
| **CLI (Pipeline B)** | Auto-generated by `docsync` from story | Not generated | `docsync <story> -o .` |

**Key rule:** Steps 1–4 artifacts may be hand-refined, but their requirement IDs (US-n, FR-n, NFR-n) must match the source story exactly. Steps 5–8 are prose and implementation; IDs still matter for traceability but prose is free-form.

## The 8 Steps (via Copilot Chat)

Start with `/run-pipeline EPMCDMETST-55568` in Copilot Chat, or walk each step manually:

### Step 1: Requirements | `.github/prompts/step-1-requirements.prompt.md`

**Input:** Jira-style story (`user-story.md`)  
**Output:** `requirements.md` with US-1, FR-1..FR-n, NFR-1, clarifications  
**Gate after:** No  
**Who:** Copilot asks clarifying questions; you answer  

### Step 2: Architecture | `.github/prompts/step-2-architecture.prompt.md`

**Input:** `requirements.md`  
**Output:** `architecture.md` with component design  
**Gate after:** No  
**Who:** Copilot designs; you refine/approve  

### Step 3: Design Review | `.github/prompts/step-3-design-review.prompt.md`

**Input:** `requirements.md`, `architecture.md`  
**Output:** `design-review.md` with risks and alternatives  
**Gate after:** **YES** — Human approval required before coding  
**Who:** Copilot identifies risks; you decide: approve, revise, or reject  

### Step 4: Implementation Plan | `.github/prompts/step-4-impl-plan.prompt.md`

**Input:** Approved `requirements.md`, `architecture.md`  
**Output:** `impl-plan.md` with task breakdown  
**Gate after:** No  
**Who:** Copilot breaks down tasks; you review  

### Step 5: Code Review | `.github/prompts/step-5-code-review.prompt.md`

**Input:** Implemented code + tests  
**Output:** `code-review.md` with findings and approval  
**Gate after:** No  
**Who:** Copilot reviews your code; you accept/revise  

### Step 6: Verification | `.github/prompts/step-7-verify.prompt.md`

**Input:** All tests passing, coverage ≥80%  
**Output:** `verification-report.md` with test summary  
**Gate after:** **YES** — Verification must pass (tests, coverage, doc quality)  
**Who:** Run: `docsync-verify . --story user-story.md` + Copilot summary  

### Step 7: Changelog | `.github/prompts/step-8-create-pr.prompt.md`

**Input:** All prior approvals  
**Output:** `CHANGELOG.md` with user-facing summary  
**Gate after:** No  
**Who:** Copilot drafts; you write the final release notes  

### Step 8: Merge & Release

**Input:** All approved artifacts  
**Output:** Merged branch, tags, GitHub Release  
**Gate after:** **YES** — CI must pass, all checks green  
**Who:** Human executes merge; CI runs verification

## Enforcement

| What | Where | Enforced by |
|---|---|---|
| Document structure + traceability | Root artifacts | `.githooks/pre-commit` (local) + `tests.yml` (CI) |
| Story-to-artifact ID parity (steps 1-4) | Generated artifacts | `doc-sync.yml` (CI) |
| Code coverage ≥80% | `tests/` | `tests.yml` (CI) |
| All 8 steps present | Merge time | `release.yml` (on tag push) |

## Quick Start

**To run the full pipeline:**

```bash
git config core.hooksPath .githooks  # One-time setup

# Then, in Copilot Chat:
/run-pipeline EPMCDMETST-55568
```

**To verify a step output locally:**

```bash
docsync-verify . --story user-story.md
```

**To auto-generate steps 1-4 from a story (CLI mode):**

```bash
docsync user-story.md -o . --phased --non-interactive
```

## Key Principles

1. **No phase skipping.** Steps go 1→8 in order. Each consumes the prior artifact.
2. **Requirement IDs are immutable.** `US-1`, `FR-1`, ... `FR-n`, `NFR-1` are derived from the source story. Prose may be refined; IDs may not.
3. **Copilot is the driver.** Steps 1-5 are Copilot Chat + prompts. Steps 6-8 include CLI verification.
4. **Traceability throughout.** Every artifact cites the requirements it addresses.
5. **Human gates at 3, 6, 8.** Not all gates are blocking, but explicit approval is expected.

See `.github/copilot-instructions.md` and `docs/copilot-operating-model.md` for implementation details.
